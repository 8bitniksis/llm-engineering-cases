# Задача 01. Классификация обращений в поддержку через LLM API

Продуктовая практика к пересдаче мока по Python. Формат: с ассистентом.
Сдаётся: промпт для ассистента + код + 3–5 предложений о ключевых решениях. После сдачи — устные вопросы по коду, как на собесе.

## Контекст

Поддержка банка получает около 50 000 обращений в день. Сейчас операторы вручную раскидывают их по отделам, обращение ждёт распределения в среднем 2 часа. Нужно автоматически относить каждое обращение к одной из 8 категорий через API языковой модели, чтобы оно сразу попадало в нужный отдел.

Каждый запрос к API платный, поэтому повторная отправка уже обработанных обращений — прямые потери денег.

## Вход и выход

**Вход** — файл JSONL, одна строка = одно обращение:

```json
{"id": "t-000123", "text": "Не приходит смс с кодом при входе в приложение"}
```

**Выход** — файл JSONL, одна строка = результат по одному обращению:

```json
{"id": "t-000123", "category": "мобильное приложение"}
```

Файл может быть большим, целиком в память не загружать.

## Категории

```
карты
кредиты
вклады
переводы и платежи
мобильное приложение
мошенничество
тарифы и комиссии
другое
```

## API модели

Реального API нет, используется заглушка с таким же поведением. Контракт:

- `async def classify(text: str) -> str` — возвращает название категории;
- одновременно разрешено **не больше 20 запросов**, при превышении — `RateLimitError` (аналог HTTP 429);
- иногда временная ошибка сервера — `ServerError` (аналог HTTP 5xx);
- иногда сервер долго не отвечает (зависание до 60 секунд);
- иногда модель возвращает строку, которой нет в списке категорий.

Заглушка — сохранить как `fake_llm.py` и не менять:

```python
import asyncio
import random

CATEGORIES = [
    "карты", "кредиты", "вклады", "переводы и платежи",
    "мобильное приложение", "мошенничество", "тарифы и комиссии", "другое",
]
MAX_CONCURRENT = 20
_in_flight = 0
calls = 0  # сколько платных запросов ушло в API


class RateLimitError(Exception):
    pass


class ServerError(Exception):
    pass


async def classify(text: str) -> str:
    global _in_flight, calls
    calls += 1
    if _in_flight >= MAX_CONCURRENT:
        raise RateLimitError("429 Too Many Requests")
    _in_flight += 1
    try:
        r = random.random()
        if r < 0.02:
            await asyncio.sleep(60)          # зависание
        else:
            await asyncio.sleep(random.uniform(0.05, 0.3))
        if r < 0.05:
            raise ServerError("503 Service Unavailable")
        if r < 0.08:
            return random.choice(["Карты.", "fraud", "не знаю", "ипотека"])  # мусор от модели
        return random.choice(CATEGORIES)
    finally:
        _in_flight -= 1
```

Тестовые данные — сгенерировать скриптом:

```python
import json, random

samples = [
    "Не приходит смс с кодом", "Списали комиссию за перевод", "Как закрыть вклад досрочно",
    "Заблокировали карту за границей", "Звонили из банка и просили код", "Не проходит платёж по QR",
    "Хочу снизить ставку по кредиту", "Приложение вылетает при входе",
]
with open("tickets.jsonl", "w", encoding="utf-8") as f:
    for i in range(2000):
        f.write(json.dumps({"id": f"t-{i:06d}", "text": random.choice(samples)}, ensure_ascii=False) + "\n")
```

## Требования

1. **Лимит API.** Скрипт никогда не превышает 20 одновременных запросов.
2. **Временные ошибки.** `RateLimitError`, `ServerError` и зависания не роняют скрипт: запрос повторяется ограниченное число раз, с паузой между попытками.
3. **Зависания.** Один запрос не может висеть дольше разумного таймаута; зависший запрос считается временной ошибкой.
4. **Ответ вне списка.** Если модель вернула категорию не из списка — результат не должен попасть в выход как есть. Решение — за вами (нормализация, повтор, категория `другое`), но его нужно обосновать.
5. **Перезапуск без двойной оплаты.** Если скрипт упал или был остановлен посередине, повторный запуск продолжает с места остановки и не отправляет в API уже обработанные обращения.
6. **Постоянные ошибки.** Если обращение не удалось обработать после всех попыток, оно не теряется молча: попадает в отдельный файл или лог с причиной.
7. **Наблюдаемость.** В конце работы — сводка: сколько обработано, сколько ушло в повторы, сколько ответов было вне списка, сколько не удалось обработать.

## Критерии приёмки

- на 2000 тестовых обращений скрипт завершается без необработанных исключений;
- в выходном файле только категории из списка, по одной записи на каждый `id`, без дублей;
- остановка через Ctrl+C посередине и повторный запуск дают полный результат, а число `fake_llm.calls` за оба запуска не больше, чем при одном запуске без остановки плюс повторы;
- все необработанные обращения перечислены с причиной;
- никогда не больше 20 одновременных запросов (в логе нет `RateLimitError` из-за собственного превышения лимита — только как редкое исключение).

## Вне рамок

- реальный API и ключи;
- качество классификации — заглушка отвечает случайно;
- веб-сервис, очереди, база данных — достаточно одного скрипта и файлов.

## Уточнения у продакта

- **Инфраструктура.** Модель крутится на общем GPU-кластере банка. Каждый запрос
  списывается с бюджета отдела по внутреннему тарифу, так что двойная отправка — всё
  равно потеря денег плюс лишняя нагрузка на кластер. Требование 5 в силе.
- **Квота.** Нашей команде — 20 одновременных запросов, больше не дадут. Это потолок,
  а не гарантия скорости: соседи по кластеру замедляют и наши запросы.
- **Нагрузка.** Средний ответ ~0,2 с. Пик — 10–13 и 18–21 МСК, ~12 % дневного объёма в
  час, ≈ 6 000 обращений/ч. В пик растёт число 429, 5xx и зависаний.
- **Режим.** Пакетный: каждые 15 минут скрипт получает файл с новыми обращениями.
  Онлайн-режим — следующий этап.

### Расчёт на салфетке

Разводим спрос и ёмкость:

- спрос: 6 000 / 3 600 ≈ 1,7 обращения/с; пакет за 15 минут ≈ 1 500 обращений;
- ёмкость: 20 / 0,2 с = 100 запросов/с; пакет уходит примерно за 15 с, а при замедлении
  кластера в 20 раз — за 5 минут, всё равно раньше следующего пакета.

Запас примерно в 60 раз, так что квота не узкое место. Узкое место — надёжность в пике:

1. **Ошибки и зависания из-за шумных соседей**: нужны таймауты и повторы.
2. **Шторм повторов**: мгновенный повтор сам добивает кластер в пик. Пауза между
   попытками должна расти.
3. **Наложение запусков**: пакет не успел за 15 минут, стартовал следующий запуск, и два
   скрипта обрабатывают одни и те же обращения. Это снова двойная оплата, поэтому
   одновременно должен работать только один запуск.

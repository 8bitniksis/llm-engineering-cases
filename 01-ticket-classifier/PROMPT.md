# Промпт для ассистента

Напиши на Python 3.11+ скрипт пакетной классификации обращений в поддержку банка через
API языковой модели. Только стандартная библиотека.

## Контекст

Поддержке приходит около 50 000 обращений в день. Каждое обращение нужно отнести к одной
из 8 категорий. Модель работает на общем GPU-кластере банка, и каждый запрос списывается
с бюджета отдела. Поэтому повторная отправка уже обработанного обращения — потеря денег.

Режим пакетный: планировщик каждые 15 минут запускает скрипт на новом файле, это около
1 500 обращений, в пик до 6 000 в час. Квота нашей команды — 20 одновременных запросов.
Ответ модели — в среднем 0,2 с, так что ёмкость около 100 запросов/с, примерно в 60 раз
выше спроса. Квота не узкое место. Узкое место — надёжность в пик: кластер нагружен
соседями, растут 429, 5xx и зависания.

## API

Заглушка `fake_llm.py` лежит рядом, менять её нельзя:

- `async def classify(text: str) -> str` возвращает название категории;
- больше 20 одновременных вызовов — `RateLimitError`;
- иногда `ServerError`;
- иногда зависание на 60 с;
- иногда строка не из `CATEGORIES` («Карты.», «fraud», «ипотека»);
- `fake_llm.calls` — счётчик платных вызовов, `fake_llm.CATEGORIES` — список категорий.

## Вход и выход

- Вход: JSONL, строки вида `{"id": "t-000123", "text": "..."}`. Файл может быть большим:
  читать построчно, целиком в память не грузить.
- `output.jsonl`: `{"id": ..., "category": ...}`, только категории из списка, по одной
  записи на `id`.
- `failed.jsonl`: `{"id": ..., "reason": ...}` — обращения, которые не удалось обработать.

Запуск: `python src/classify.py <input.jsonl>`. Пути к базе, выходным файлам и
блокировке — аргументы с разумными значениями по умолчанию.

## Решения, которые нужно реализовать

1. **Один запуск за раз.** На старте берётся блокировка ОС на файл `classify.lock`:
   `fcntl.flock` с `LOCK_NB` на POSIX, `msvcrt.locking` с `LK_NBLCK` на Windows, то есть
   без ожидания. Если она занята,
   скрипт пишет в лог «предыдущий запуск ещё работает» и выходит с кодом 0. Флаг-файл
   («создал — значит занято») не годится: после падения он остаётся висеть, а блокировку
   ОС снимает сама.
2. **Состояние в SQLite.** Таблица `results(id TEXT PRIMARY KEY, status TEXT, category
   TEXT, reason TEXT)`, `status` — `ok` или `failed`. Результат пишется сразу по
   готовности, коммит на каждую запись. Перед отправкой обращение проверяется по
   базе: если `id` уже есть в любом статусе, в API оно не уходит. Так перезапуск после
   Ctrl+C или падения теряет только запросы, которые были в полёте, — не больше 20.
3. **Лимит.** `asyncio.Semaphore(20)` держится только на время самого вызова
   `classify`. На паузу перед повтором слот отпускается.
4. **Ограниченная память.** В работе одновременно не больше ~100 задач: следующая строка
   входа читается, только когда освободилось место. Не создавать корутину на каждую
   строку файла сразу.
5. **Таймаут.** Каждый вызов обёрнут в `asyncio.wait_for(..., 10)`. 10 с — вдвое больше
   худшего нормального ответа в пик (0,2 с × 20 = 4 с). Таймаут — временная ошибка.
6. **Повторы.** Временные ошибки: `RateLimitError`, `ServerError`, таймаут, ответ вне
   списка. Всего до 4 попыток. Пауза перед повтором n (n = 1, 2, 3) —
   `random.uniform(0, min(8, 0.5 * 2**n))`, то есть экспоненциальная с full jitter. Без
   случайной составляющей 20 упавших запросов повторились бы в один момент и сами
   добивали бы кластер в пик.
7. **Ответ вне списка.** Сначала нормализация: `strip`, `lower`, убрать знаки
   препинания по краям («Карты.» → «карты»). Если после неё ответ в списке — принимаем.
   Если нет — это временная ошибка, повторяем. В «другое» такие ответы не кладём: так
   ошибка модели молча отправит, например, обращение о мошенничестве не в тот отдел. Если
   попытки кончились, обращение уходит в failed на ручную разметку.
8. **Постоянные ошибки.** После 4 неудачных попыток пишется `status=failed`, в `reason`
   — последняя ошибка: `timeout`, `server_error`, `rate_limit` или `invalid_category:
   <сырой ответ>`. Ни одно обращение не теряется молча.
9. **Выгрузка.** В конце запуска `output.jsonl` и `failed.jsonl` целиком
   перезаписываются из базы. Так файлы всегда полные и без дублей, сколько бы ни было
   перезапусков.
10. **Сводка в конце.** Сколько обработано за этот запуск, сколько пропущено как уже
    готовые, сколько было повторов, сколько ответов вне списка (отдельно — исправленных
    нормализацией), сколько отказов, `fake_llm.calls`. Сводка печатается и при Ctrl+C:
    перехватить `KeyboardInterrupt` / `CancelledError`, закоммитить готовое, выгрузить
    файлы, напечатать сводку.

## Тесты

Файл `tests/test_classify.py` на `unittest`. Вместо `fake_llm.classify` подставляется
детерминированный фейк. Проверить:

- нормализацию: «Карты.» → «карты»; «fraud» не проходит;
- повтор после `ServerError` с успехом на второй попытке;
- уход в failed с причиной после 4 неудачных попыток;
- второй запуск на тех же данных не делает ни одного вызова API;
- одновременно в полёте не больше 20 вызовов: фейк считает пик;
- таймаут: фейк, который спит дольше таймаута, считается временной ошибкой. В тесте
  таймаут и паузы уменьшить через параметры, чтобы тест шёл секунды.

## Критерии приёмки

- 2000 обращений из `data/sample.jsonl` обрабатываются без необработанных исключений;
- в `output.jsonl` только категории из списка, ровно одна запись на `id`;
- Ctrl+C посередине, затем повторный запуск дают полный результат, а `fake_llm.calls`
  за оба запуска — не больше, чем при одном запуске без остановки, плюс повторы и не
  больше 20 вызовов, бывших в полёте в момент остановки;
- все необработанные обращения перечислены в `failed.jsonl` с причиной;
- `RateLimitError` из-за собственного превышения лимита не возникает.
